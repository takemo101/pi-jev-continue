# pi-jev-continue

Jev の判定で pi の開発ループを継続する extension。実装・調査・コマンド実行は pi のモデルが担当し、Jev は次の作業種別・継続条件と、開発中の選択肢形式の質問への回答を判断します。

通常の継続回数は **無制限**。指定した目標の範囲で、実装 → 検証 → 修正・改善を繰り返します。Jev が判断できない場合や人の入力が必要な場合まで強制的に回し続けるものではありません。

## 必要なもの

- **pi 0.87.1 以降**の `@earendil-works/pi-coding-agent`。動作確認版は 0.87.1。
- Node.js 24.12 以降。
- pi の開発用モデルとその認証。
- TypeSafe の `TYPESAFE_API_KEY`。pi のモデル用 API キーとは別です。

旧 `@mariozechner/pi-coding-agent` 向けの互換コードは含めていません。`agent_before_settle` を提供する pi が必要です。

## インストール

GitHub から直接インストールできます。

```bash
pi install git:github.com/takemo101/pi-jev-continue
```

ローカルに取得済みの場合は、このディレクトリの親から実行します。

```bash
pi install ./pi-jev-continue
```

起動中の pi では `/reload`。グローバル設定に追加せず試す場合は、開発対象のディレクトリで次のように起動します。

```bash
export TYPESAFE_API_KEY='your-typesafe-api-key'
pi -e /absolute/path/to/pi-jev-continue/src/index.ts
```

npm への公開・ユーザーの pi 設定への自動インストールは行っていません。pi が TypeScript を読み込み、スキーマには pi が提供する `typebox` を使います。`.env` は自動ロードしないので、キーは起動する pi の環境に渡してください。

## 対話モード

```text
/jev-on このリポジトリのCSVパーサーを完成させ、境界値テストを実行し、エラー処理を改善する。公開APIは変更しない。
```

有効化すると、その目標で最初の開発ターンも開始します。各反復の末尾で pi に「実施内容・実行証拠・人に依存する障害・具体的な次の作業」を報告させ、その報告を Jev が評価します。

| コマンド | 動作 |
| --- | --- |
| `/jev-on <目標>` | 目標を設定し、方針ファイルを読み込み、カウンターをリセットして開始。実行中の目標変更は拒否 |
| `/jev-on` | 同じセッションの直前の目標で再開。方針ファイルを再読み込みし、カウンターをリセット |
| `/jev-off` | 自動継続を無効化。判定中の Jev リクエストと `jev_choose` の回答待ちも中断 |
| `/jev-status` | 有効状態・継続回数・上限・判定レベルとしきい値・直近の状態・目標・適用方針の読み込み元・履歴件数・JSONL 保存先を表示 |
| `/jev-max <n>` | 自動継続回数の上限を設定。`0` は無制限。カウンターはリセットしない |
| `/jev-history <n>` | Jev に付加する直近の会話件数を設定。既定10件、`0` は履歴の付加なし |
| `/jev-level <1〜5>` | 継続・選択判定の厳しさを設定。1が最も緩く、5が従来どおりの既定値。引数なしで現在値を表示 |

上限は「最初の実行を除いた自動継続回数」です。`/jev-max 10` なら最初の実行＋最大10回の継続。実行中の `jev_choose` 呼び出しはこの回数に含みません。最初は小さい上限で挙動を確認することを推奨します。

フッターには有効状態・継続回数・直近の状態を表示します。**同じセッション内で有効状態を解除する操作は `/jev-off` だけ**です。通常のメッセージは現在の自動処理より優先しますが、有効状態・目標・継続回数・上限は維持し、その入力後の報告から判定を再開します。`Jev on` は設定が有効という意味で、必ずしも実行中ではありません。停止中は停止理由を表示し、入力を待ちます。

### 停止とセッション

- **Jev の正常な停止判定**: 今回の自動継続だけを止め、`enabled` は `true` のまま次の会話を待ちます。待機中に同じ報告を再判定せず、次の入力後の報告から再び判定します。目標・継続回数・上限は維持し、停止理由も状態表示に残します。
- **通信・検証・ログ保存の失敗、タイムアウト、pi のエラー・中断・開始失敗**: 現在の自動処理を止めて入力待ちにしますが、無効化はしません。自動リトライは行わず、次の通常入力から判定を再開します。
- **上限到達**: 無効化せず入力待ちにします。通常入力や停止ではカウンターをリセットせず、上限を超えた自動継続もしません。続ける場合は `/jev-max` で上限を変更してから通常入力するか、`/jev-on` でカウンターをリセットして開始します。上限変更だけでは実行を開始しません。
- **`jev_choose` の人への委譲**: `enabled` を変更せず回答を待ちます。有効だった場合は、人の回答後も同じ目標・継続回数・上限で自動判断を続けます。未回答なら作業は停止し、次の人の入力を待ちます。
- **Escape**: TUI の現在の自動処理・判定・質問の回答待ちを取り消します。有効状態は維持し、次の通常入力を待ちます。pi 本来の中断操作も通します。
- **`/jev-off`**: 自動継続を無効化し、`jev_choose` の回答待ちも止めます。以後の通常入力では Jev を再開せず、再度 `/jev-on` が必要です。それ以外の実行中の開発用モデルやツール自体は中断しないため、それも止める場合は Escape を使ってください。
- `/new`、セッション切替、fork、tree 移動、reload、再起動後は、自動では再開しません。目標と上限はセッション開始時に初期化し、履歴件数も既定10件、判定レベルも既定5へ戻します。起動時は CLI の指定値を適用します。
- RPC では `prompt` コマンドで `/jev-off` を送ると、Jev 判定中でも直ちに停止できます。
- **pi 0.87.1 の RPC `abort` 制約**: 継続判定境界では `ctx.signal` が提供されないため、ネイティブ `abort` だけではその Jev HTTP 待ちを直ちに中断できません。次の開発ターンは開始されませんが、応答または30秒のタイムアウトまで settlement が遅れます。継続判定も即時中断するには `/jev-off` を使用してください。ツール実行中の `jev_choose` はネイティブ `abort` でも中断します。

## 判定の厳しさを5段階で設定する

`/jev-level` と起動時の `--jev-level` は、継続判定・選択式質問の両方に共通で適用します。**5が従来と同じ既定値、1が最も緩い設定**です。

| レベル | 確信度の下限 | 人への依存度の上限 | 目標・継続条件への適合度の下限 |
| --- | --- | --- | --- |
| 1（最も緩い） | 0.65 | 0.30 | 0.70 |
| 2 | 0.70 | 0.25 | 0.75 |
| 3 | 0.75 | 0.20 | 0.80 |
| 4 | 0.80 | 0.15 | 0.85 |
| 5（既定・従来どおり） | 0.85 | 0.10 | 0.90 |

```text
/jev-level 3
/jev-status
```

- 設定できるのは整数の `1`〜`5` のみです。小数・範囲外・不正文字を丸めたり補完したりしません。不正なコマンドは以前の設定を維持し、不正な起動フラグは CLI による自動有効化を止めます。
- **次の判定から適用**します。送信済みの判定は開始時のレベルで評価し、回答待ちの質問を新しい設定で再判定しません。目標・方針・継続回数・有効状態は変更せず、停止済みの処理や人の回答待ちを自動再開しません。
- セッション内の設定で、永続化はしません。起動時に指定する場合は `pi --jev-level 3 ...` を使います。`CONTINUE.md` の文章からレベルを変更することはできません。
- 低いレベルほど範囲外の作業や人の判断が必要な質問も通りやすくなります。数値は運用上のプリセットであり、校正済みの安全確率ではありません。目標外・完了後の不要作業・停止指示の事例も含めて挙動を評価してください。
- `requiresApproval: true` の強制的な人への引き継ぎ、`other` / `defer`、不正応答時の停止、中断、継続上限は、どのレベルでも維持します。緩和しても操作権限を与えるものではありません。

## CONTINUE.md による継続方針

次の2ファイルに、任意のMarkdownで「どこまで進めるか」「どの判断を任せるか」「いつ質問・停止するか」を記載できます。必須の見出しやYAMLスキーマはありません。ファイルは自動作成しません。

| ファイル | 適用範囲 |
| --- | --- |
| `~/.pi/CONTINUE.md` | 個人共通の方針。OSのホームディレクトリを使用 |
| `./.pi/CONTINUE.md` | piの起動ディレクトリの方針。親ディレクトリやGitルートは探索しない |

両方を読み込み、矛盾する条件は **現在の明示的なユーザー指示 → プロジェクト方針 → 個人方針 → 既定動作** の順に扱うようモデルへ指示します。矛盾しない下位の条件は残ります。「実装を続ける」といった広い目標だけでは、方針に書かれた停止・確認条件を解除しません。一方、ユーザーが通常作業の確認条件を明示的に変更した場合は、その指示を優先します。目標外の仕事を方針ファイルで追加することもできません。

例：要求達成で止めるプロジェクトの `./.pi/CONTINUE.md`。

```markdown
# 継続方針

## 任せる判断
- 依頼した目標内の通常の実装方法・調査方法・作業順序。
- ローカル計画の作成・修正と、その範囲内の実装・検証。
- 委任済みの通常判断は、理由を報告して進める。

## 継続条件
- 要求の未実装部分、既知の不具合、未実施の必須検証が残っている。

## 人に確認する条件
- 目標や受け入れ条件を変える必要がある。
- 人だけが提供できる情報や、新たな操作許可が必要である。

## 停止条件
- 受け入れ条件を満たし、必要な検証が成功した。
- 完了後の任意のリファクタリングや追加機能には進まない。
```

品質改善まで任せるなら、上記の継続・停止条件を次のように置き換えます。

```markdown
## 継続条件
- 要求達成後も、具体的な問題と検証方法を示せる品質改善は続ける。

## 停止条件
- 次の改善について、問題の根拠や効果の確認方法を示せない。
```

**同じ方針を開発モデル・継続判定・質問判定へ共有します。** 継続判定では、次作業の分類、人への未解決の依存、目標と継続・停止条件への適合を独立に評価します。質問判定では、候補の選択・人への依存・候補の適合に方針を適用します。ファイル内容や優先順位の意味解釈はモデルが行うため、決定的なルールエンジンではありません。曖昧な記述や競合で確信度が不足すれば、停止・人への委譲になる場合があります。

### 読み込み・更新・制限

- `/jev-on` による有効化時、または `--jev-goal` の初回プロンプトで読み込み、本文・読み込み元をその有効化のスナップショットとして固定します。反復・通常メッセージ・人の回答では再読み込みしません。
- 編集を反映するには現在の実行を止めて `/jev-on` を再実行してください。モデルがファイルを書き換えても、実行中の適用方針は変わりません。新規セッション・reload後は再度有効化が必要で、ログから方針を自動復元しません。
- ファイル未配置・空の本文は追加条件なしとして扱います。両方未配置なら既定動作です。同じパスになる場合はプロジェクト方針として1回だけ読みます。`PI_CODING_AGENT_DIR` を変更しても個人方針の場所は変わりません。
- 通常のUTF-8ファイルのみ、**2ファイル合計8000バイト以内**です。読み込み不能・不正UTF-8・通常ファイル以外・サイズ超過では、その有効化を開始しません。部分的な方針や切り詰めた本文にはフォールバックしません。
- 再有効化が失敗した場合は、その場の自動処理を停止して入力を待ち、以前の目標とスナップショットは置き換えません。有効だった設定も維持するため、以後の通常入力は以前の方針で再開できます。初回のCLI有効化失敗でも、通常プロンプト自体のpiによる処理は止めません。
- 方針は会話履歴件数と独立して渡します。`--jev-history 0` でも除去しません。方針のパス・本文を含む送信state全体には、既存の24000 UTF-8バイト上限も適用します。
- `/jev-status` は適用中の読み込み元を表示します。全文は有効化時の `jev-continue-state.policy` と、送受信JSONLのリクエスト本文内 `state.policy` に記録します。各要素は `scope`、`path`、`text` です。

**方針ファイルは操作権限ではありません。** 破壊的操作・デプロイ・購入・権限変更・秘密情報へのアクセス・外部作用を承認する用途には使えません。`requiresApproval: true` の人への引き継ぎ、しきい値、不正応答時の停止、中断・継続上限はコード側に残ります。「最大10回」のような厳密な制御には、文章ではなく `/jev-max 10` を使ってください。

方針の本文と絶対パスは開発モデル・TypeSafeへ送信され、ログにも保存されます。秘密情報は書かず、リポジトリ由来の方針も有効化前に確認してください。

### CONTINUE.md authoring skill

The package includes the English agent skill [`create-continue-policy`](skills/create-continue-policy/SKILL.md). It guides agents to create durable continuation rules without copying current plans, issue IDs, progress, or historical approvals into the policy.

With the package's skills enabled, invoke:

```text
/skill:create-continue-policy Create a reusable project-level CONTINUE.md.
```

When loading only the extension with `-e`, load the skill explicitly:

```bash
pi -e /absolute/path/to/pi-jev-continue/src/index.ts \
  --skill /absolute/path/to/pi-jev-continue/skills/create-continue-policy
```

Creating a policy does not enable automation. Review it before `/jev-on`.


## Jev に渡す会話履歴

継続判定と選択肢の判定の両方に、`conversation` として **直近最大10件の user／assistant の公開テキスト**を追加します。1件は1メッセージで、1往復ではありません。発言者を `role`、本文を `text` に入れ、古い順に並べます。

履歴は pi のモデルに書き直させず、拡張が現在の会話コンテキストから抽出します。質問判定では読み取り専用の `sessionManager.buildSessionProjection()`、継続判定では `agent_before_settle` の `contextMessages` を使用します。現在の分岐・圧縮後のコンテキストが対象で、別の分岐や圧縮前の原文を復元して混ぜません。独立した圧縮要約・custom メッセージは抽出対象外です。

thinking、画像、ツール呼び出しの引数、ツール結果は `conversation` に含めず、公開テキストが空のメッセージは件数に数えません。継続判定の最新報告は `latestReport` に入るため重複させず、その報告より前の発言を履歴として選びます。

対話中の変更:

```text
/jev-history 20
/jev-status
```

起動時は `--jev-history 20` を指定します。非負の整数のみ受け付けます。コマンドの変更は次の Jev リクエストから適用し、送信済みのリクエストは変更しません。設定は永続化しません。`0` は `conversation: []` にする設定で、目標・報告・質問などの既存の入力は引き続き送信します。

件数指定より古い発言は対象外ですが、選んだ発言の本文は切り詰めません。**方針と履歴を含む state 全体は24000 UTF-8バイト以内**に制限し、超過時は履歴を自動で減らすのではなく、自動判断を止めます。必要なら履歴件数や方針の長さを減らしてください。

Jev にはユーザーの制約・過去の選択を考慮し、assistant の提案をユーザーの承認として扱わないよう指示します。ただし、範囲外・圧縮済みの古い制約まで保持する永続的な意思決定記憶ではなく、すべての制約を認識する保証もありません。

## 選択肢への自動回答

`/jev-on` 中は、pi に専用ツール **`jev_choose`** で選択肢形式の質問を出すよう指示します。追加の開始コマンドは不要です。たとえば「オフライン・DBサーバー不要」という目標に対する PostgreSQL / SQLite の選択では、Jev が条件に合う選択肢を返し、pi がその回答で作業を続けます。

これは自由文からの質問抽出や、他 extension の選択ダイアログへの自動キー入力ではありません。**pi が `jev_choose` を使った質問だけが対象**です。`--tools` でツールを制限する場合は `jev_choose` も含めてください。

ツール入力は `question`、`context`、2〜8個の `options`（`label` と `description`）、`requiresApproval` の構造化データです。ラベルは重複不可。質問は最大2000文字、補足は6000文字、各ラベルは160文字、各説明は1600文字で、目標・適用方針・拡張が取得した会話履歴を含めた送信 state は24000 UTF-8バイト以内です。履歴や方針をツール引数としてモデルに生成させることはありません。

- **自動回答**: 選択レベルの確信度・人依存度・選んだ候補の適合度の条件をすべて満たす場合のみ。既定レベル5では confidence ≥ 0.85、人への依存 ≤ 0.10、適合度 ≥ 0.90 です。先頭の選択肢や既定値で代用しません。
- **人へ確認**: `requiresApproval: true` は Jev に送信せず、必ず人に渡します。Jev の人依存度が選択レベルの上限を超えた場合も自動回答しません。レベルを緩めても、承認・認証情報・支払い・破壊的操作・外部操作の許可を自動的に与えることはできません。
- **低確信度・情報不足・通信失敗**: 自動回答せず、人に渡します。`enabled` は維持し、回答待ち中は継続判定と後続ツールの実行を止めます。質問自体が不正なら、選択せず人の入力を待ちます。
- **TUI / RPC**: TUI は質問・背景・委譲理由・選択肢を分けた専用表示、RPC はホスト標準の選択・入力ダイアログを使います。有効だった場合は、人の回答後に pi の処理・継続判定・次の質問の自動回答を続けます。`/jev-on` の再実行は不要で、目標・カウンター・上限はリセットしません。元から無効だった場合は、人が回答しても有効化しません。HTTP の30秒制限は人の回答待ちには適用しません。
- **非対話モード**: 質問と選択肢をツール結果および stderr に出し、回答を仮定せず停止します。`enabled` は維持します。
- **キャンセル・未回答**: ツール呼び出しを終了し、後続ツールとモデルの続行を止めます。新しい人の入力、明示的な再開、セッションの初期化まで未解決状態を保持します。Escape を含む質問の取消では無効化しません。`/jev-off`・セッション切替による無効化は優先し、中断後の遅れた Jev 応答や UI 回答は採用せず、有効状態も復元しません。

Jev には、選択、質問全体の人への依存、候補ごとの目標・継続条件への適合を1回のリクエストで独立に問い合わせます。すべての応答形式を検証したうえで、選ばれた候補の適合度だけを回答条件に使います。ほかの候補が目標外でも、それだけでは妥当な回答を止めません。

`jev_choose` は単独で呼ぶようモデルに指示します。同一バッチの後続ツールも未回答時には拒否しますが、すでに実行された操作を取り消すことはできません。自動回答は人の承認を代行せず、pi 全体の権限制御を置き換えません。

### 人への質問 UI と補足

質問は1件ずつ、既存の選択肢から1つを選ぶ形式を維持します。モデルには、ユーザーの言語で具体的な判断を尋ね、ラベルは短く、説明には結果・制約・トレードオフを書くよう指示します。依頼済みの通常作業の再確認と、新たな承認が必要な判断を区別するようにも指示します。質問 UI 自体は判定レベルや承認要件を変更しません。

通常の判断を任せるか、人の確認を必要とするかはユーザー指示と適用方針に従います。既定では、委任済み作業の再承認は求めません。質問の人依存判定は、背景に書かれた将来の実操作ではなく、その質問でまだ解決していない人への依存を対象にします。上位の指示で置き換えた通常判断の確認条件は再要求しませんが、`requiresApproval: true` を自動判断で解除することはなく、操作に必要な承認を方針ファイルや通常作業の委任で代行しません。

TUI では `ask_user_question` と同じ pi 標準の `DynamicBorder` を使い、質問・選択肢・補足入力を上下のアクセント色の枠線で区切ります。枠内の上下には1行、本文・補足エディタの左右には1文字分の余白を設け、選択肢の説明と折り返し行はラベルの開始位置に揃えます。操作ヒントは下側の枠線から1行空けて表示し、スクロール中や補足編集中も枠線を維持します。余白を含めて端末幅と高さを計算し、高さが足りない場合は空行を省いて入力欄・エラー・操作ヒントを優先します。テーマに追従し、pi 本体のフッターが隠れない高さに収めます。

**TUI の操作（既定のキー）**

- `↑` / `↓`: 回答候補と、末尾の `Add/edit note (optional; not an answer)` を移動。ラベルと説明は別の行に表示します。
- `Enter`: 回答候補では回答を送信し、`Add/edit note` では任意の補足の入力欄を開きます。補足は回答候補とは別の操作項目で、`n` キーによる入力切替はありません。
- 補足には、たとえば「SQLite。ただし既存データの移行は今回は不要」という条件を添えられます。保存後に回答候補を選び直し、`Enter` で送信します。再び `Add/edit note` を選ぶと保存済みの補足を編集できます。
- 補足の編集では `Shift+Enter` / `Ctrl+J` で改行、`Enter` で保存して選択肢へ戻ります。**補足を保存しただけでは回答を送信しません。**
- `PageUp` / `PageDown`: 長い背景・説明・補足をスクロール。狭い画面では折り返し、選択中の候補と操作ヒントを表示します。
- `Escape`: 補足の編集中も質問全体を取消。有効状態は維持し、次の通常入力を待ちます。

**RPC の操作**

通常の選択肢を選ぶと、そのまま回答を送信します。末尾の `Add/edit note` を選ぶと補足の入力欄を開き、保存後に補足を表示した選択ダイアログへ戻ります。入力欄は全文置き換えで、現在の補足はプレースホルダーとして渡します。どちらのダイアログでも取消は質問全体の取消です。

補足は任意で、前後の空白を除いて2000文字以内（JavaScript の文字列長）です。空欄で保存すると補足を削除し、長すぎる場合は切り詰めず修正を求めます。改行は保持します。補足は選択肢とは別の `details.notes` とツール結果本文に入れ、開発モデルへ返します。**補足だけで質問を解決済みにしたり、別の操作への追加承認として扱ったりはしません。** 自由入力による選択肢の置き換え、複数選択、質問タブ、プレビューは追加していません。


## 非対話モード

開発対象のディレクトリで実行します。

```bash
export TYPESAFE_API_KEY='your-typesafe-api-key'
pi -e /absolute/path/to/pi-jev-continue/src/index.ts \
  --jev-goal 'CSVパーサーを実装・検証し、公開APIを維持してエラー処理を改善する' \
  --jev-max 10 \
  --jev-history 10 \
  --jev-level 5 \
  --print '目標に沿って開発を開始してください'
```

`--jev-max 0` または省略で無制限です。`--jev-goal` は起動後の最初のプロンプトで有効になります。flag だけではモデル実行を開始しないので、非対話モードではプロンプトも渡してください。通常の入力が pi の実行を開始するため、キー不足で自動継続を有効化できなかった場合も、その通常入力の処理は行われます。

環境変数:

| 名前 | 用途 |
| --- | --- |
| `TYPESAFE_API_KEY` | TypeSafe の Bearer 認証キー。必須 |
| `TYPESAFE_MODEL` | Jev のモデル名。既定は `jev-1.13.0` に固定 |
| `JEV_LOG_DIR` | 送受信 JSONL の保存ディレクトリ。既定は pi の agent ディレクトリ内の `jev-continue/logs` |

モデルや質問文・しきい値の変更後は、実際の開発報告・質問を使って判定を再評価してください。下記の実 API 確認は限定した実ログと合成例によるもので、実務全般での判定精度やしきい値校正を保証しません。

## 判定と制御

`agent_end` のたびにタイマーでメッセージを送り込むのではなく、pi の最終的な継続判断境界 `agent_before_settle` を使います。1回の HTTP リクエストで3問を並列評価します。

| 質問 | 型 | 継続条件（既定レベル5） |
| --- | --- | --- |
| 最新報告で提案された次の具体的な作業は何か | Choice | `implement` / `fix` / `verify` / `improve` で、confidence ≥ 0.85 |
| その次作業に、未提供の人の判断・情報・認証・承認が必要か | Noul | `needs_human` ≤ 0.10 |
| その次作業は指定目標と適用中の継続・停止条件に適合するか | Noul | `in_scope` ≥ 0.90 |

選択レベルの条件をすべて満たした場合のみ、コードで選んだ作業指示を次ターンに追加します。Jev 自体にはコードや次の指示文を生成させません。`other`、確信度不足、適合度不足、人依存度の上限超過で停止します。具体的で有用な次の作業がなくなった場合も停止します。

3問とも、最新報告で提案された直後の具体的な作業（複数ある場合は先頭）を対象にします。Issue・要件・既存計画の閲覧や調査は `verify`、未完成のコード・計画・文書の作成は `implement`、完成済み成果物の改善は `improve` として区別します。目標に個々のIssue番号や調査手順が列挙されていなくても、依頼した作業の具体的な下位手順かを評価します。

たとえば「次のIssueを読む」は、そのIssueのコード着手や実キー登録とは別の作業です。後段の実操作の未承認・保留Issue・未検証の能力を、それらを使わない閲覧やオフライン検証の障害にしません。ファイル・Issue・ツール結果の調査で取得できる情報も、人だけが提供できる情報とは区別します。反対に、直後の作業自体に必要な承認・認証情報は省略しません。報告には「次作業に必要な人の入力」と「後段の制限」を分けて書かせ、明示された停止指示や個別承認要件を優先します。

以下も停止条件です。

- Jev の HTTP エラー・不正応答・30秒のタイムアウト。extension 独自の自動リトライはしません。
- pi の失敗・中断、または完了していない assistant 応答。pi 本体の既存リトライ・圧縮は、この判定境界より前に処理される場合があります。
- ユーザー入力・待機中のメッセージ・設定した継続上限。
- 報告の欠落・過大な判定入力。

別の extension がすでに継続を要求している境界では、重ねて Jev を呼びません。ただし他 extension のループを制御するものではないため、`pi-auto-continue` など同種の自動継続 extension は無効にして使ってください。

## 外部送信と安全性

`/jev-on` または `--jev-goal` を使うと、継続判定では次の情報を **`https://api.typesafe.ai/v1/systemone` に送信**します。

- 指定目標（最大4000文字）。
- 最新の assistant 報告（最大12000文字）と前回の報告。
- 直近の user／assistant の公開発言。既定10件、`--jev-history` / `/jev-history` で変更可能。
- 最新ユーザーメッセージ以降の直近6件のツール結果。ツール名・失敗フラグ・テキスト出力の先頭2000文字・省略フラグ。
- コードで計算した反復番号。
- 適用中の継続方針の本文・絶対パス・適用範囲（`policy`）。

継続判定の抽出対象には thinking、画像、ツール引数、tool details、セッション全履歴を含めません。`jev_choose` の自動回答では、目標・適用方針・明示的なツール入力（質問・補足・選択肢・承認要否）と、拡張が抽出した会話履歴を送信します。どちらも JSON 化した state 全体に24000 UTF-8バイトの上限を設けます。入力が上限を超えた場合は、判断材料を黙って切り捨てず自動判断を止めます。継続判定のツール出力だけは明示的に省略します。

**方針ファイル・会話履歴・ツール結果・報告・質問・補足・選択肢に秘密情報が含まれていれば、それも送信され、送受信 JSONL に保存され得ます。自動的な秘密情報の除去は保証しません。** 方針の本文はpiの有効化ログにも保存します。人が入力した回答への補足もツール結果として開発モデルに渡り、後続の継続判定のツール出力などに含まれる場合があります。方針や補足欄に認証情報を入力しないでください。機密リポジトリで有効にする前に、TypeSafe への送信可否を確認してください。

Jev の確信度は正しさの保証ではありません。入力内の指示を無視するよう質問を設計していますが、プロンプトインジェクションを防ぐセキュリティ境界ではありません。継続判定は反復終了後に行い、質問の制御は `jev_choose` に限定されるため、危険なツール実行すべてを個別に承認・阻止する仕組みではありません。

無制限モードは pi と Jev の API 利用・ファイル変更を継続できます。分離した作業ディレクトリ、バックアップ、pi 側の権限制御、必要なら継続上限を併用してください。

## ログと開発

### リクエスト・レスポンスの JSONL

継続判定と `jev_choose` の **すべての Jev HTTP リクエスト・レスポンスを自動記録**します。pi のセッションログとは別のファイルなので、**`--no-session` でも保存されます**。追加の有効化操作は不要です。

既定の保存先は次のとおりです。`PI_CODING_AGENT_DIR` が設定されていれば、その agent ディレクトリを使います。

```text
~/.pi/agent/jev-continue/logs/<起動日時>-<PID>-<UUID>.jsonl
```

`/jev-status` で現在のファイルの絶対パスを確認できます。保存先の変更例:

```bash
export JEV_LOG_DIR="$HOME/jev-logs"
pi -e /absolute/path/to/pi-jev-continue/src/index.ts
```

1行が1イベントの JSON です。共通フィールドは `version`、UTC の `timestamp`、送受信を対応付ける `requestId`、`event` です。

| `event` | 記録内容 |
| --- | --- |
| `request` | 送信前に記録。URL、HTTP メソッド、指定モデル、リクエスト本文全体 |
| `response` | HTTP ステータス、開始から本文読み取りまでの `durationMs`、レスポンス本文全体、中断済みかを示す `aborted` |
| `error` | 通信失敗・中断・本文読み取り失敗・不正 JSON の区分 `kind` と経過時間。取得できた場合は HTTP ステータス |

`body` は **HTTP 本文の文字列**です。改行を JSON エスケープするため、本文に改行があっても1イベント1行を保ちます。正常なレスポンスだけでなく、HTTP エラーの本文、不正 JSON、判断には採用しない中断後の遅いレスポンスも残します。本文の読み取りに失敗した場合は `body: null` とエラー区分を記録します。自由形式の低レベル例外や `signal.reason` は保存しません。

送信前に入力検証で拒否した場合や、すでに中断されていて HTTP を実行しない場合は、送信ログを作りません。HTTP 200 の記録があっても、回答が拡張側の形式検証・しきい値判定で採用されたとは限りません。

判定に使ったレベルは、pi セッションの `jev-judgment.level` / `jev-choice-judgment.level` に記録します。送受信 JSONL は HTTP 本文の記録であり、ローカルのしきい値はモデルに送信しません。レベルを変更しても、進行中の判定の記録は開始時の値のままです。

**認証ヘッダーは記録せず、設定された TypeSafe API キーが本文に混入した場合もマスクします。ただし、その他の認証情報・コード・個人情報は本文に含まれるまま保存され得ます。** 新しいディレクトリは `0700`、ファイルは `0600` で作成します（POSIX）。既存ディレクトリの権限は変更しません。

別プロセスや reload 後は別ファイルに書き込み、同一ファイルには同期追記します。送信前の書き込みに失敗したら HTTP を送らず、レスポンスの記録に失敗したらその回答を採用せず停止／人へ引き継ぎます。強制終了・電源断・ディスク障害まで含めた完全保存は保証できず、応答未着のリクエストだけが残ることもあります。

本文の切り詰め・ログの自動削除は行いません。長時間の自動運転ではログ容量が増えるため、保管期間・バックアップ・削除は利用側で管理してください。

### pi セッション内の判定ログ

セッションに次の custom entry を保存します（`--no-session` ではメモリ内のみ）。

- `jev-judgment`: 判定開始時の `level`、選択した action、停止理由、元の answers と確率分布、実モデル名、usage。
- `jev-choice-judgment`: 判定開始時の `level`、検証済みの回答／委譲 action、理由、自動回答時の `optionIndex`（0始まり）。質問本文や生の API メタデータはこの entry には保存しません。
- `jev-continue-state`: 有効化・停止・レベル変更時の状態、継続カウンター、現在の `level`。有効化時には目標と適用方針 `policy`（読み込み元・全文）も記録。

これらの custom entry はモデルの会話コンテキストには挿入しません。`jev_choose` の呼び出しとツール結果は通常どおり会話に残り、回答結果の `source` で `jev` / `human` を区別します。継続判定の TypeSafe usage は記録しますが、pi の開発用モデルの料金表示には合算しません。永続ログから自動運転を復元することもありません。

```bash
npm ci --ignore-scripts
npm run check
npm test
```

実装は pi ライフサイクル、方針ファイルの読み込み、継続判定、質問ツール、質問判定、共通 HTTP クライアント、JSONL 保存、入力抽出に分離しています。

### 保守時の変更箇所

| 変更したい内容 | 主な場所 |

| Jev への質問 | `src/jev.ts` の `questions` |

保守時も、次の不変条件を維持してください。

- 停止・再開・セッション切替では、HTTP の中断に加えて世代番号を更新し、古い応答で新しい実行を操作しない。
- `await` の前後の確認は単なる重複ではない。判定中の入力・上限変更・中断を結果適用前にも確認する。
- 応答形式の検証と運用ポリシーは分離する。不正応答は自動判断を止める。正常な継続停止は `action: "stop"`、質問の人への委譲は `action: "defer"` で区別する。
- 質問文・しきい値の変更は挙動変更として扱う。単なる整理では、既存の質問・しきい値・停止理由の優先順位を変えない。
